## Difficulty lessons (from Sol results)

- [2026-11-12] FAILS difficulty — `harbor-replication-brace-expansion` was EASY for GPT-6.1 Sol: PPP, ~8 min and ~10k output tokens per trial. Why: (1) instruction.md listed every rule and edge case with expected outputs, so it became "implement this spec"; (2) the whole fix was one pure function in one file; (3) the hidden tests checked exactly the listed cases; (4) the existing doc comment ("doesn't support more than one {") pointed straight at the function. → For hard tasks: describe only symptoms plus the general expected behavior and let the agent find the cause; make the fix need changes in 2+ layers/packages; put the root cause away from the symptom; keep edge cases implied by "must stay consistent with X" rather than listed; avoid bugs whose location is advertised by a code comment.
- [2026-11-12] NOTE how to judge — open `jobs/<run>/<trial>/result.json`: agent `started_at`/`finished_at` and `n_output_tokens`. Under ~15 min / ~15k tokens with a pass means the task is easy, whatever the outcome string says.

## Network / answer-leak lessons

- [2026-11-12] FAILS leakage — `network_mode = "public"` lets the solver reach GitHub. Upstream `main` already contains part of the retention task's fix: `20ccb7778 fix(retention): avoid stripping repository path twice (#23546)`, merged after base 0a6bf30d. The image also kept the `origin` remote, so `git fetch origin main && git log -- performer.go` would hand over the root cause. (The brace task has no upstream fix, so its PPP result is clean.) → Before finalizing a task, check upstream: `git log --oneline <base>..origin/main -- <files in solution.patch>`. If a fix exists upstream, block network access to it, and still prefer bugs that aren't fixed upstream.
- [2026-11-12] WORKS lockdown — Harbor 0.25 supports `[environment] network_mode = "allowlist"` + `allowed_hosts = [...]` (validated with harbor's `TaskConfig`; the docker backend enforces it with an egress-control sidecar). Codex on a ChatGPT login only needs `chatgpt.com` (inference) and `auth.openai.com` (token refresh), so the allowlist is `["chatgpt.com", "*.chatgpt.com", "openai.com", "*.openai.com"]`. In the Dockerfile: `git remote remove origin`, delete `.git/FETCH_HEAD`, and after warming the caches set `ENV GOPROXY=off GOTOOLCHAIN=local`. Verified: oracle = 1 inside `docker run --network none`. → Use this for every new task. If Sol trials come back `E` with connection errors to some other OpenAI host, add only that host.
- [2026-11-12] NOTE leakage that can't be blocked — the model may already know a public upstream fix from training. → Prefer bugs with no upstream fix; for tasks partly fixed upstream, put most of the difficulty in the parts that aren't (here: fail-closed on rule errors, one rule load per project, per-digest and no-stale-cache traps).

- [2026-11-12] NOTE why it was still easy, despite the symptom-only instruction:
  (1) The instruction named the subsystems ("tag retention", "immutability rules"). Sol's first command was `rg --files ... '*immutable*' '*retention*'` and the second `rg 'NewRuleMatcher|ParseRepository|Repository:'`, so the search space was tiny.
  (2) Each symptom maps to one visible code smell in the same ~40-line function: `ParseRepository` on an already-stripped name, `log.Error(err); return false`, and `NewRuleMatcher()` inside the per-candidate loop. Three symptoms aren't three hard problems when they point at the same spot.
  (3) The traps (per-digest protection, no stale cache in the shared matcher) only catch a solver who takes a detour. A strong model's natural fix (snapshot the rules per run, keep the per-hash logic) never goes near them.
  (4) "Nested repositories" + "UI badge works" practically says "compare how the two paths compute the repository name".
- [2026-11-12] NOTE for future hard tasks:
  - The bug must not be a visible smell next to the symptom's obvious entry point. It should come from an interaction: two individually reasonable pieces of code that are wrong together, in different packages, ideally with state or ordering involved (concurrency, pagination, caching across requests, retries).
  - Describe symptoms in user/API terms, without the internal subsystem names that grep straight to the code.
  - The fix should need new behavior or design (a contract change propagated through several callers), not deleting one bad line.
  - Make the hidden tests require the full contract on cases the instruction implies but doesn't list, so a local patch at the first smell fails.
  - Judge by time/tokens as well as outcome: under ~10 min / ~10k tokens = easy.
